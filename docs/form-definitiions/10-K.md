# 10-K Filing Structure

This note describes the golden annual filing:

[`golden/golden-10-K.txt`](../golden/golden-10-K.txt)

It is Microsoft's Form 10-K for the fiscal year ended June 30, 2026. The
submission identifies Microsoft Corporation as CIK `0000789019` and has
accession number `0001193125-26-323660`.

## Submission Container

The file is an SEC full-submission text container. It contains an SEC header
followed by many `DOCUMENT` blocks, rather than being one standalone XML
document:

```text
<SEC-DOCUMENT>
  <SEC-HEADER>...</SEC-HEADER>
  <DOCUMENT>
    <TYPE>10-K</TYPE>
    <FILENAME>msft-20260630.htm</FILENAME>
    <TEXT>
      <XBRL>Inline XHTML and XBRL</XBRL>
    </TEXT>
  </DOCUMENT>
  <DOCUMENT>...</DOCUMENT>
</SEC-DOCUMENT>
```

The submission header reports 130 public documents. The important document
groups are:

- `msft-20260630.htm`: the human-readable annual report with embedded Inline
  XBRL.
- `msft-20260630.xsd`: Microsoft's extension taxonomy.
- `R1.htm` through `R112.htm`: generated XBRL presentation reports.
- `FilingSummary.xml`: report and instance metadata.
- `MetaLinks.json`: taxonomy and report relationship metadata.
- `msft-20260630_htm.xml`: normalized XBRL instance data.
- `0001193125-26-323660-xbrl.zip`: an XBRL package, uuencoded inside the
  submission.
- Exhibits including the auditor consent, subsidiaries exhibit, certifications,
  clawback policy exhibit, and other annual-report attachments.

The submission is approximately 214,000 lines and 36 MB. The SEC wrapper,
HTML, XBRL, generated reports, JavaScript, CSS, JSON, and uuencoded ZIP data
are all mixed into that one text file.

## Inline XBRL Facts

The primary document uses the Inline XBRL namespace:

```xml
xmlns:ix="http://www.xbrl.org/2013/inlineXBRL"
```

Across the submission, the XBRL markers include approximately:

- 1,583 `ix:nonFraction` numeric facts
- 286 `ix:nonNumeric` text facts
- 446 contexts
- 6 units
- 1,192 explicit dimension members
- 4 typed dimension members
- 59 `ix:continuation` elements

A numeric fact has a taxonomy name and references its context and unit:

```xml
<ix:nonFraction
    id="F_..."
    name="us-gaap:Assets"
    contextRef="C_..."
    unitRef="U_USD"
    scale="6"
    decimals="-6"
    format="ixt:num-dot-decimal">
  619,858
</ix:nonFraction>
```

Important attributes include:

- `name`: the taxonomy concept, such as `us-gaap:Assets`.
- `contextRef`: the entity, period, and dimensional context.
- `unitRef`: the unit, such as USD or shares.
- `scale`: the display multiplier; `6` commonly represents millions.
- `decimals`: the reported precision.
- `format`: the Inline XBRL transformation rule.
- `sign`: an explicit negative sign when present.
- `xsi:nil`: indicates that no value is reported.
- `continuedAt`: points to text continued in an `ix:continuation` element.

Text facts use `ix:nonNumeric`. Facts in `ix:hidden` contain document metadata
or supporting facts that are not visibly displayed. Annual filings generally
have more contexts, dimensions, extension concepts, and narrative facts than
quarterly filings.

## Contexts and Units

A context gives a fact its meaning. It may contain the CIK, an instant or
duration period, and dimensional qualifiers:

```xml
<xbrli:context id="C_...">
  <xbrli:entity>
    <xbrli:identifier scheme="http://www.sec.gov/CIK">
      0000789019
    </xbrli:identifier>
    <xbrli:segment>
      <xbrldi:explicitMember dimension="srt:RangeAxis">
        srt:MaximumMember
      </xbrldi:explicitMember>
    </xbrli:segment>
  </xbrli:entity>
  <xbrli:period>
    <xbrli:instant>2026-06-30</xbrli:instant>
  </xbrli:period>
</xbrli:context>
```

This filing uses:

- instant periods such as June 30, 2026;
- duration periods covering the fiscal year or portions of it;
- explicit dimensions such as business segments, instruments, geographies,
  and member categories;
- typed dimensions for facts whose dimensional values are not predefined
  taxonomy members.

Units are referenced separately. The six units include USD, EUR, shares,
pure numbers, a Microsoft segment unit, and a USD-per-share divide unit:

```xml
<xbrli:unit id="U_UnitedStatesOfAmericaDollarsShare">
  <xbrli:divide>
    <xbrli:unitNumerator>
      <xbrli:measure>iso4217:USD</xbrli:measure>
    </xbrli:unitNumerator>
    <xbrli:unitDenominator>
      <xbrli:measure>xbrli:shares</xbrli:measure>
    </xbrli:unitDenominator>
  </xbrli:divide>
</xbrli:unit>
```

## Taxonomies and Relationships

The filing uses standard and Microsoft-specific namespaces, including:

```text
us-gaap  http://fasb.org/us-gaap/2025
dei      http://xbrl.sec.gov/dei/2025
msft     http://www.microsoft.com/20260630
srt      http://fasb.org/srt/2025
ecd      http://xbrl.sec.gov/ecd/2025
cyd      http://xbrl.sec.gov/cyd/2025
```

`us-gaap` and `dei` concepts are standardized. `msft` concepts are Microsoft
extensions. The extension schema and embedded linkbases define concepts,
labels, presentation relationships, calculation relationships, and dimensional
metadata. Footnote relationships connect facts to narrative explanations.

## Normalized Instance

The preferred extraction source is `msft-20260630_htm.xml`, near the end of the
submission. It is a conventional XBRL instance document with contexts, units,
and facts:

```xml
<xbrl xmlns="http://www.xbrl.org/2003/instance">
  <link:schemaRef xlink:href="msft-20260630.xsd" xlink:type="simple"/>
  <context ...>...</context>
  <unit ...>...</unit>
  <us-gaap:Assets
      contextRef="C_..."
      unitRef="U_USD"
      decimals="-6">
    619858000000
  </us-gaap:Assets>
</xbrl>
```

`FilingSummary.xml` describes this instance using:

```text
ContextCount: 446
ElementCount: 548
EntityCount: 1
SegmentCount: 128
ScenarioCount: 0
UnitCount: 6
```

The `R*.htm` files are report views generated from the same XBRL model. They
are useful for understanding presentation and table grouping, but the
normalized instance is the better source for semantic fact extraction.

## Extraction Approach

The recommended first implementation is:

1. Parse the SEC submission envelope and isolate each `DOCUMENT` block.
2. Select `msft-20260630_htm.xml` when it is available.
3. Parse the normalized instance with a namespace-aware XML parser.
4. Build maps for context ID, unit ID, and concept QName.
5. Iterate through facts and resolve each fact's context and unit.
6. Preserve dimensions, decimals, scale, sign, and the original value.
7. Load the Microsoft XSD when concept labels, data types, or relationships are
   needed.
8. Use the Inline XBRL HTML only when visible placement, narrative text, or
   table presentation is important.

A useful fact model is:

```text
Fact
  Concept
  Namespace
  Value
  ContextID
  UnitID
  Period
  EntityCIK
  Dimensions
  Decimals
  Scale
  Sign
```

The main complications are the SEC wrapper, XHTML presentation markup, Inline
XBRL transformation rules, continuation chains, hidden facts, dimensional
contexts, footnotes, and company extension concepts. The normalized instance
avoids most XHTML handling while retaining the annual filing's semantic XBRL
data.
