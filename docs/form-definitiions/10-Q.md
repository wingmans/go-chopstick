# 10-Q XBRL Structure

This note describes the structure of the golden filing:

[`golden/0000950170-25-010491.txt`](../golden/0000950170-25-010491.txt)

The filing is Microsoft's Form 10-Q for the period ended December 31, 2024.

## Submission Container

The file is an SEC full-submission text container rather than one standalone
XML document:

```text
<SEC-DOCUMENT>
  <SEC-HEADER>...</SEC-HEADER>
  <DOCUMENT>
    <TYPE>10-Q</TYPE>
    <FILENAME>msft-20241231.htm</FILENAME>
    <TEXT>
      <XBRL>Inline XHTML and XBRL</XBRL>
    </TEXT>
  </DOCUMENT>
  <DOCUMENT>...</DOCUMENT>
</SEC-DOCUMENT>
```

Relevant documents in the submission include:

- `msft-20241231.htm`: the human-readable filing with embedded Inline XBRL.
- `msft-20241231.xsd`: Microsoft's extension taxonomy.
- `R1.htm` through `R90.htm`: generated presentation reports.
- `FilingSummary.xml`: report and instance metadata.
- `MetaLinks.json`: taxonomy and report relationship metadata.
- `msft-20241231_htm.xml`: normalized XBRL instance document.
- `0000950170-25-010491-xbrl.zip`: an XBRL package, uuencoded inside the submission.

The submission header identifies the filer as Microsoft Corporation, CIK
`0000789019`, with form type `10-Q`.

## Inline XBRL

The primary 10-Q document uses the Inline XBRL namespace:

```xml
xmlns:ix="http://www.xbrl.org/2013/inlineXBRL"
```

The primary document contains approximately:

- 1,392 `ix:nonFraction` numeric facts
- 188 `ix:nonNumeric` text facts
- 409 contexts
- 5 units
- 1 schema reference
- 1,136 explicit dimension members
- 2 typed dimension members

A numeric fact typically looks like this:

```xml
<ix:nonFraction
    id="F_..."
    name="us-gaap:NetIncomeLoss"
    contextRef="C_..."
    unitRef="U_USD"
    scale="6"
    decimals="-6"
    format="ixt:num-dot-decimal">
  24,108
</ix:nonFraction>
```

Important fact attributes are:

- `name`: the taxonomy concept.
- `contextRef`: the entity, period, and dimensional context.
- `unitRef`: the unit, such as USD or shares.
- `scale`: the displayed value multiplier; `6` means millions.
- `decimals`: the reported precision.
- `format`: the Inline XBRL transformation rule.
- `sign`: an explicit negative sign when present.
- `xsi:nil`: indicates that the fact has no value.
- `continuedAt`: points to text continued in an `ix:continuation` element.

Text facts use `ix:nonNumeric`. Some facts are hidden in `ix:hidden`, usually
because they support the XBRL model but are not visibly displayed in the
report.

## Contexts and Units

Facts are only meaningful when their context is resolved. A context can define
the CIK, an instant or duration period, and one or more dimensions:

```xml
<xbrli:context id="C_...">
  <xbrli:entity>
    <xbrli:identifier scheme="http://www.sec.gov/CIK">
      0000789019
    </xbrli:identifier>
    <xbrli:segment>
      <xbrldi:explicitMember dimension="srt:StatementGeographicalAxis">
        us-gaap:NonUsMember
      </xbrldi:explicitMember>
    </xbrli:segment>
  </xbrli:entity>
  <xbrli:period>
    <xbrli:startDate>2024-10-01</xbrli:startDate>
    <xbrli:endDate>2024-12-31</xbrli:endDate>
  </xbrli:period>
</xbrli:context>
```

Contexts may use:

- instant periods, such as `2024-12-31`;
- duration periods, such as October 1 through December 31, 2024;
- explicit dimensions;
- typed dimensions.

Units are referenced separately:

```xml
<xbrli:unit id="U_USD">
  <xbrli:measure>iso4217:USD</xbrli:measure>
</xbrli:unit>
```

## Taxonomies and Relationships

The filing uses standard and company-specific namespaces, including:

```text
us-gaap  http://fasb.org/us-gaap/2024
dei      http://xbrl.sec.gov/dei/2024
msft     http://www.microsoft.com/20241231
srt      http://fasb.org/srt/2024
ecd      http://xbrl.sec.gov/ecd/2024
```

`us-gaap` and `dei` concepts are standardized. `msft` concepts are Microsoft
extensions. The XSD and embedded linkbases define concepts, labels,
presentation relationships, calculation relationships, and dimensional
metadata.

The `R*.htm` files are presentation views, useful for reproducing SEC-style
tables but not ideal as the primary source for fact extraction.

## Normalized Instance

The most convenient extraction source is `msft-20241231_htm.xml`. It contains a
conventional XBRL instance with contexts, units, and facts:

```xml
<xbrl xmlns="http://www.xbrl.org/2003/instance">
  <link:schemaRef .../>
  <context ...>...</context>
  <unit ...>...</unit>
  <us-gaap:Assets
      contextRef="C_..."
      unitRef="U_USD"
      decimals="-6">
    619858000000
  </us-gaap:Assets>
</xbrl>
```

`FilingSummary.xml` reports the same core model dimensions:

```text
ContextCount: 409
ElementCount: 373
EntityCount: 1
SegmentCount: 104
UnitCount: 5
```

## Extraction Approach

The recommended first implementation is:

1. Parse the SEC submission envelope and isolate each `DOCUMENT` block.
2. Prefer `msft-20241231_htm.xml` when it is available.
3. Parse the normalized instance with a namespace-aware XML parser.
4. Build maps for context ID, unit ID, and concept QName.
5. Iterate over facts and resolve each fact's context and unit.
6. Preserve dimensions, decimals, scale, sign, and the original value.
7. Later compare the normalized instance with the Inline XBRL facts in
   `msft-20241231.htm`.

A useful fact model is:

```text
Fact
  Concept
  Namespace
  Value
  ContextID
  UnitID
  Period
  EntityCIK
  Dimensions
  Decimals
  Scale
  Sign
```

The main parsing complications are XHTML embedded around the facts, numeric
transformation rules, continuation chains, hidden facts, dimensional contexts,
and company extension concepts. The normalized instance avoids most XHTML
handling while retaining the semantic XBRL data.
