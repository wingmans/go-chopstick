# 8-K Filing Structure

This note describes the golden current report:

[`golden/golden-8-K.txt`](../golden/golden-8-K.txt)

It is Microsoft's Form 8-K filed April 29, 2026. The submission identifies
Microsoft Corporation as CIK `0000789019` and has accession number
`0001193125-26-191457`.

## Submission Container

The file is an SEC full-submission text container. It contains an SEC header
and ten `DOCUMENT` blocks:

```text
<SEC-DOCUMENT>
  <SEC-HEADER>...</SEC-HEADER>
  <DOCUMENT>
    <TYPE>8-K</TYPE>
    <FILENAME>msft-20260429.htm</FILENAME>
    <TEXT>
      <XBRL>Inline XHTML and XBRL</XBRL>
    </TEXT>
  </DOCUMENT>
  <DOCUMENT>...</DOCUMENT>
</SEC-DOCUMENT>
```

The submission is approximately 6,100 lines and 1 MB. Its documents are:

| Type | Filename | Purpose |
| --- | --- | --- |
| `8-K` | `msft-20260429.htm` | Main current report with Inline XBRL metadata |
| `EX-99.1` | `msft-ex99_1.htm` | Microsoft third-quarter earnings release |
| `EX-101.SCH` | `msft-20260429.xsd` | Microsoft extension taxonomy |
| `XML` | `R1.htm` | Generated document/entity information report |
| `XML` | `FilingSummary.xml` | XBRL report and instance metadata |
| `JSON` | `MetaLinks.json` | Taxonomy and report relationship metadata |
| `ZIP` | `0001193125-26-191457-xbrl.zip` | XBRL package, uuencoded in the submission |
| `XML` | `msft-20260429_htm.xml` | Normalized XBRL instance |

The SEC header includes two reported items:

- Item 2.02, Results of Operations and Financial Condition
- Item 9.01, Financial Statements and Exhibits

## Main 8-K Report

The first document is an XHTML current report. Its visible content includes:

- Form 8-K identification;
- report date of April 29, 2026;
- Microsoft Corporation's name and CIK-related cover information;
- Item 2.02 reporting the results announcement; and
- Item 9.01 identifying the attached financial information.

The main report does not contain a full set of financial statements. It points
to the earnings release in Exhibit 99.1.

## Exhibit 99.1

`msft-ex99_1.htm` is the substantive business document. It is an earnings
release titled:

```text
Microsoft Cloud and AI Strength Fuels Third Quarter Results
```

It announces results for the quarter ended March 31, 2026 and compares them
with the corresponding period of the prior year. The release contains:

- revenue, operating income, net income, and diluted EPS highlights;
- GAAP and non-GAAP comparisons;
- Microsoft Cloud and segment highlights;
- management commentary;
- reconciliation tables;
- forward-looking statements; and
- media and investor contact information.

The numerical values in this exhibit are presented as ordinary HTML text and
table content. They are not represented by `ix:nonFraction` facts in this
golden file. Therefore, extracting the earnings figures requires HTML/table
extraction or text parsing, rather than an XBRL fact reader.

## Inline XBRL Content

The main 8-K declares the Inline XBRL namespace:

```xml
xmlns:ix="http://www.xbrl.org/2013/inlineXBRL"
```

The submission contains approximately:

- 28 `ix:nonNumeric` facts;
- 0 `ix:nonFraction` facts;
- 0 `ix:fraction` facts;
- 4 contexts;
- 0 units;
- 6 explicit dimension members; and
- 0 typed dimension members.

The Inline XBRL facts are primarily document/entity metadata, for example:

```xml
<ix:nonNumeric
    name="dei:DocumentType"
    contextRef="C_...">
  8-K
</ix:nonNumeric>
```

The hidden XBRL metadata includes facts such as the entity CIK and amendment
flag. The cover page also tags the document period end date and registrant
name. No numeric financial fact is tagged in the main 8-K or its earnings
release in this submission.

## Contexts

The four contexts all use Microsoft CIK `0000789019` and the report date of
April 29, 2026. Three contexts include an explicit stock-class dimension:

```xml
<xbrli:context id="C_...">
  <xbrli:entity>
    <xbrli:identifier scheme="http://www.sec.gov/CIK">
      0000789019
    </xbrli:identifier>
    <xbrli:segment>
      <xbrldi:explicitMember
          dimension="us-gaap:StatementClassOfStockAxis">
        msft:CommonStockMember
      </xbrldi:explicitMember>
    </xbrli:segment>
  </xbrli:entity>
  <xbrli:period>
    <xbrli:startDate>2026-04-29</xbrli:startDate>
    <xbrli:endDate>2026-04-29</xbrli:endDate>
  </xbrli:period>
</xbrli:context>
```

The fourth context has no segment. Although these contexts are present, the
filing's XBRL facts are still metadata-only. A context by itself does not imply
that financial statements or numeric facts are available.

It also marks the input instance as `isOnlyDei="true"`. This confirms that

## Normalized Instance

The normalized instance is `msft-20260429_htm.xml`, near the end of the
submission. It is a conventional XBRL document containing:

- one `link:schemaRef` to `msft-20260429.xsd`;
- four contexts; and
- metadata facts, but no numeric units or numeric financial facts.

Its structure is still suitable for a namespace-aware XML parser:

```xml
<xbrl xmlns="http://www.xbrl.org/2003/instance">
  <link:schemaRef xlink:href="msft-20260429.xsd" xlink:type="simple"/>
  <context ...>...</context>
  <dei:DocumentType contextRef="C_...">8-K</dei:DocumentType>
</xbrl>
```

The normalized instance is the right source for the 28 metadata facts. It is
not the right source for the earnings-release financial values because those
values are only present as HTML text.

## Extraction Approach

This filing requires two extraction paths:

1. Parse the SEC submission envelope and isolate each `DOCUMENT` block.
2. Parse `msft-20260429_htm.xml` for document/entity XBRL metadata.
3. Resolve the four contexts and their stock-class dimensions.
4. Parse `msft-ex99_1.htm` as HTML for the earnings-release narrative and
   tables.
5. Treat the exhibit's GAAP and non-GAAP values as presentation data unless
   they can be validated through another structured source.

For XBRL metadata, a small fact model is sufficient:

```text
Fact
  Concept
  Namespace
  Value
  ContextID
  EntityCIK
  Dimensions
```

For the earnings release, the important additional model is table-oriented:

```text
Report
  Title
  ReportDate
  PeriodEndDate
  Sections
  Tables
    RowLabel
    Columns
    Values
    Units
```

The key assessment result is that this 8-K is XBRL-enabled at the filing
metadata level, but it is not a numeric XBRL financial statement filing. A
general extractor must therefore support filings where XBRL metadata exists
while substantive financial data remains in HTML exhibits.
